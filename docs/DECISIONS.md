# Kararlar (tek satır gerekçeli)

Biçim: `Dn — karar — gerekçe`

- **D1 — Yığın: depodaki gerçek yığın korunur (Android/Kotlin + Supabase + Claude); prompt'taki Firebase/Swift/Gemini ifadeleri bu yığına eşlenir.** — Prompt `KampusAgi-iOS`, Firestore ve Gemini varsayıyor ama bunlar bu depoda yok; canlı Supabase projesi + 24 migration + 4 Edge Function çalışıyor, Firebase'e dönmek çalışan altyapıyı atmak olurdu. Clean Architecture Domain arayüzleri backend'den bağımsız; ileride Firebase isteniyorsa yalnızca `data/` ve `di/` katmanı yeniden yazılır.
- **D1a — Eşleme:** Firestore Rules → Postgres RLS · Cloud Functions → Supabase Edge Functions + Postgres trigger/RPC · Firebase custom claim `admin` → JWT `app_metadata.role` (`is_admin()` SQL fonksiyonu) · Firestore snapshot listener → Supabase Realtime (Postgres Changes) · Emulator Suite rules testleri → gerçek Supabase projesinde (branch) SQL testleri + `get_advisors`.
- **D2 — Eski Firebase projesi (`Desktop\dosyalar\kampüs ağı`) salt-okunur referans.** — Başka bir repo, farklı paket adı; içine dokunmak kapsam dışı ve geri alınamaz risk. Yalnızca Etkinlikler REST sözleşmesi (`CampusEventApi.kt`) okunur.
- **D3 — İhtiyaç analizi sağlayıcısı Claude kalır; arayüzde marka adı yerine "AI ANALİZİ" yazılır.** — Sunucu Claude çağırıyor (kullanıcının 2026-09-14 kuralı: "Claude yalnızca backend'den"); ekranda "GEMINI" yazıp Claude çağırmak kullanıcıya yanlış bilgi olurdu. Metin `strings.xml`'de tek noktada, sağlayıcı değişirse tek satır.
- **D4 — Push (FCM) ve Crashlytics kurulmaz; bildirimler Supabase Realtime + uygulama içi bildirim listesiyle karşılanır.** — Gerçek `google-services.json`/Firebase projesi yok (dış erişim, BLOCKERS B1); ayrıca kullanıcı 2026-09-16'da "FCM'yi iptal et" dedi. Hata raporlama `ErrorReporter` arayüzüyle soyutlanır (şimdilik Logcat), Crashlytics gelince tek sınıf eklenir.
- **D5 — iOS'a özgü maddeler Android karşılığıyla uygulanır:** Asset Catalog → `Color.kt`+`MaterialTheme`; Localizable.xcstrings → `strings.xml`; Privacy Manifest → Play Data Safety notu (`docs/RELEASE_NOTES.md`); StoreKit 2 → Google Play Billing; swift-snapshot-testing → Roborazzi/Paparazzi eşdeğeri; "Apple ile Devam Et" düğmesi Android'de konmaz (kullanıcı 2026-09-16'da açıkça "istemiyorsan kaldır" demişti).
- **D6 — Derleme araç zinciri:** AGP 9.x + Gradle 9.3.1 + Kotlin/KSP/Compose, makinede çalıştığı kanıtlı `Desktop\sss` projesiyle aynı desen (`compileSdk { version = release(36) { minorApiLevel = 1 } }`, yerleşik Kotlin); SDK'da yalnızca platform 36.1/37.0 var. Sürümler Maven metadata'dan en son *stable* seçildi.
- **D7 — `git init` yapıldı, küçük commit'ler atılır.** — Prompt §0.3 commit istiyor; depo git'siz idi. `.gitignore` sırları (`.env`, `local.properties`, `serviceAccount*`) dışarıda tutar.
- **D8 (REVİZE) — Gönderi sayaçları `posts.like_count/comment_count` sütunlarında, security definer tetikleyicilerle tutulur.** — İlk karar (view'da `count(*)`) YANLIŞTI: view `security_invoker` ve `post_likes` RLS'i yalnızca kullanıcının kendi beğenisini gösterdiği için sayaç herkeste 0/1 çıkıyordu (SQL testiyle yakalandı, migration 202609190005). Prompt'un istediği tetikleyicili sayaç çözümüne dönüldü; istemci sayaçları değiştiremez (`protect_post_fields`).
- **D9 — Buton yüksekliği 48dp → 50dp, giriş kutusu köşesi 12dp → 10dp, kart köşesi 16dp → 14dp** — Yeni şartname (§2.3) önceki Android tasarım mesajının yerine geçer (kullanıcı: yeni bilgi eskiyi geçersiz kılar). Renkler zaten aynıydı (`#4F46E5`/`#818CF8`).
- **D10 — "Bitti" satırı yazılmaz.** — Release build + tüm testler + rules testleri + tüm ekranlar tamamlanmadan `DURUM: TAMAMLANDI` yazmak §0.7'yi ihlal eder ve `kesintisiz-calistir.ps1` döngüsünü erken durdurur.
- **D11 — Avatar baş harf rengi `primaryContrast` (açıkta beyaz, koyuda koyu).** — Şartname "beyaz baş harf" diyor ama §4 kontrast şartı koyu temada beyaz/`#818CF8` (≈2.9:1) için sağlanmıyor; token zaten bu amaçla tanımlı.
- **D12 — Kayıt sihirbazı adım 2-5 içeriği `profiles` şemasından türetildi** (ad soyad+kullanıcı adı / üniversite / bölüm / özet). — Prompt §3.1 "eksikse tamamla, gerçek backend'e bağla" diyor; hiçbir adım uydurma alan içermez, hepsi `profiles` sütunlarına yazar. KVKK/onay adımı eklenmedi: hukuki metin benim yazacağım şey değil.
- **D13 — Kök yönlendirme durumları:** Loading / Unauthenticated / Onboarding(adım 2 veya 6) / PendingReview / Rejected / Approved / LoadFailed. Durum okunamazsa eski "güvenli taraf = Pending" davranışı kaldırıldı (kullanıcıya yalan söylerdi); hata + "Tekrar Dene" gösterilir.
- **D14 — Belge doğrulama istemcide:** 10 MB sınır okuma sırasında, `%PDF-` imzası (MIME beyanına güvenilmez). Bucket limitiyle aynı, sunucu ayrıca doğrular.
- **D15 — Testler ASCII sürücüde (K:) çalışır.** — Yol `kampusagıios` içerdiği için Gradle test işçisi sınıf yolunu çözemiyor (kanıtlandı: ClassNotFoundException); `scripts/ensure-k-drive.ps1` idempotent `subst` yapar.
- **D16 — Admin/moderatör bayrakları `app_metadata.is_admin` / `is_moderator` (boolean)** (D1a'daki "role" anlatımı düzeltildi; mevcut `is_admin()`/`is_moderator()` bunları okuyor). İlk admin SQL ile atanır (docs/ADMIN.md), sonrası `set-user-role` Edge Function'ıyla.
- **D17 — Belge onayı tek RPC (`review_student_verification`), moderatörün doğrudan `student_verifications` UPDATE'i kapatıldı.** — Doğrudan UPDATE `document_path/user_id` gibi sütunları da değiştirebilirdi; ayrıca eski akış `protect_profile_privileged_fields` `auth.role()` (JWT rolü) kullandığı için sync tetikleyicisinde kendi korumasına takılıp HİÇ çalışmıyordu → `current_user` + security invoker (202609190004). Bulgu SQL testleriyle yakalandı.
- **D18 — Advisor "SECURITY DEFINER callable" uyarıları bilinçli:** `is_admin/is_moderator/current_university_id/is_account_active/match_requirements` RLS politikalarında çağıran rolle çalıştığı için `authenticated`/`anon` EXECUTE gerektirir ve yalnızca çağıranın kendi bilgisini döndürür; `review_student_verification` içeride `is_moderator()` denetler, `anon` çağıramaz (testli).
- **D19 — Alt gezinme sekme etiketi "İhtiyaç"; ekran başlığı "İhtiyaç Oluştur".** — 5 sekmeli çubukta "İhtiyaç Oluştur" 11sp'de sığmıyor/kesiliyor; şartname yalnızca ekran başlığını metin olarak sabitliyor.
- **D20 — Sohbet yalnızca RPC ile başlar (`start_conversation`); `conversation_members` INSERT politikası kaldırıldı.** — Eski politika herkese herhangi bir sohbete üye olma izni veriyordu ve `conversation_members_select` kendi kendini çağırıp sonsuz özyinelemeye (42P17) düşüyordu; sohbet hiç çalışmıyordu. `is_conversation_member()` SECURITY DEFINER yardımcısı + RPC (202609190007/0008, `supabase/tests/003_chat_rules.sql` ile canlıda doğrulandı).
- **D21 — Canlı sohbet özel Realtime kanalında (`chat:<id>`, `realtime.messages` politikalarıyla yetkili):** mesaj INSERT + karşı tarafın `last_read_at` UPDATE'i (Postgres Changes), yazıyor (broadcast), çevrimiçi (presence). Kanal koparsa VM üstel geri çekilmeyle (2→30 sn) yeni oturum açar ve kaçan mesajları REST ile yeniden çeker; Realtime hatası uygulamayı çökertmez.
- **D22 — Gönderim idempotent:** istemci UUID'si mesaj kimliğidir; aynı kimlikle yeniden deneme çift kayıt üretmez (PG 23505 → mevcut satır döner). Çevrimdışı kuyruk YALNIZCA bellekte (süreç ölürse bekleyen mesaj kaybolur; "Gönderilemedi · Tekrar denemek için dokun" ile kullanıcı yeniden dener). - **D24 — Eşleşme skoru normalize edildi** (yalnızca hesaplanabilen bileşenlerin ağırlıklı toplamı 0–100; önceden en çok %25 çıkıyordu) ve `parse-need` onaysız hesaplarda reddediliyor (Claude bütçesi suistimali). "Geç" (kaydırma) sunucuda saklanmaz, oturum içidir.
